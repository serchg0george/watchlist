# Что посмотреть

Личный трекер фильмов, сериалов и шоу для двоих — S и L. Список «хочу посмотреть», отметки просмотренного, у каждого просмотренного две отдельные оценки 1–10 (S и L) и статистика по каждому и вместе. Данные хранятся в файле `data/movies.json` этого репозитория; сайт коммитит их через GitHub API с токеном пользователя.

Сайт: <https://serchg0george.github.io/watchlist/> (репозиторий `serchg0george/watchlist`, ветка `master`).

Все могут **смотреть** список без входа. **Редактировать** могут только люди с правом записи в репозиторий — через токен, который один раз вставляется в настройках сайта.

## Как редактировать

1. Создайте персональный токен GitHub (Settings → Developer settings → Personal access tokens):
   - **владелец репозитория** — Fine-grained tokens → Generate new token; Repository access: только `serchg0george/watchlist`; Permissions: **Contents — Read and write**;
   - **второй человек (коллаборатор)** — Tokens (classic) → Generate new token (classic); scope только **`public_repo`**. Fine-grained токен коллаборатору не подходит: GitHub пускает его только в репозитории его собственного аккаунта.
2. Откройте сайт, нажмите ⚙ в шапке, вставьте токен в поле «Токен» и нажмите «Сохранить». Кто вы, сайт определит по логину: владелец репозитория (`serchg0george`) — S, любой другой логин с правом записи — L (константа `OWNER_LOGIN` в `app.js`). Звёзды можно ставить только в своей строке; чужая оценка видна рядом, но не редактируется. Так же и с комментариями: под элементом кнопка «💬 Комментарий» для своего комментария, чужой виден, но не редактируется.

Сайт проверит токен запросом к `GET /user`, запомнит ваш логин (в `localStorage`) и покажет его в шапке: «Редактирует: \<логин\>». После этого появляются форма добавления, чекбоксы, звёзды и кнопка редактирования ✎. Кнопка «Выйти» удаляет токен из браузера.

Токен хранится только в `localStorage` вашего браузера и никуда не отправляется, кроме запросов к GitHub API от вашего имени.

## Удобства

- **Поиск TMDB.** В поле добавления введите русское или оригинальное название, ссылку TMDB (`/movie/…`, `/tv/…`) или IMDb (`/title/tt…`). Выберите результат, проверьте год и категорию, затем нажмите «Добавить выбранное». Постер, описание, жанры и длительность сохраняются вместе с записью, если доступны. Для сериалов длительность относится к серии. IMDb используется для поиска совпадения в TMDB; Кинопоиск не подключён. При отсутствии результатов можно добавить название вручную.
- **Подключение TMDB.** В настройках ⚙ вставьте **API Read Access Token** из своего аккаунта TMDB и нажмите «Сохранить TMDB». Токен хранится только в этом браузере, отправляется только API TMDB и не записывается в данные или репозиторий. На каждом устройстве настройка отдельная; «Удалить токен TMDB» удаляет его из браузера. API-ключ v3 не нужен. Данные и изображения предоставлены [TMDB](https://www.themoviedb.org/); атрибуция размещена в настройках.
- **Черновики и сохранение.** Поле добавления, выбранный результат и текст редакторов восстанавливаются из локальных черновиков. При ошибке записи изменения остаются на странице, появляется «Повторить сохранение», последующие записи ждут повтора. Не закрывайте страницу с несохранёнными изменениями: очередь операций хранится в памяти; браузер предупреждает при выходе. Черновики текста сохраняются отдельно, но не заменяют очередь для оценок, статусов и удалений. Успешно сохранённый черновик очищается; новый текст не стирается завершением предыдущей записи.
- **Компактный список и телефон.** Подробности, оценки и комментарии раскрываются в карточке. На телефоне есть кнопка быстрого перехода к добавлению, крупные элементы управления и прокручиваемые настройки. Поиск (в том числе по оригинальному названию), фильтры, сортировка и позиция прокрутки запоминаются в браузере. «Сбросить фильтры» возвращает активный список.
- **Установка на телефон.** Android/Chrome: меню → «Установить приложение». iPhone/Safari: «Поделиться» → «На экран „Домой“». Открывается без адресной строки; без интернета показывается последняя загруженная версия списка.
- **«🎲 Что посмотреть сегодня?»** — случайный элемент из «Хочу посмотреть» с учётом фильтра по типу; строка подсвечивается.
- **Управление категориями.** Кнопка «Категории» в шапке (или пункт в фильтре типов и в настройках ⚙): переименование категорий, добавление новых и выбор цвета из палитры.
- **Отмена.** После отметки «просмотрено» и удаления 5 секунд доступна кнопка «Отменить».
- **Автоматические даты.** При каждом переходе в «Просмотрено» или «Брошено» ставится сегодняшняя дата по местному времени. В редакторе её можно исправить вручную; обычное редактирование названия или заметки дату не меняет. Для брошенного хранится отдельная дата, не входящая в календарь просмотров.
- **Жанры.** В редакторе ✎ укажите один или несколько жанров через запятую, например «комедия, драма». Повторы и лишние пробелы убираются; старые записи остаются без жанров, пока вы их не заполните.
- **Дубли.** При добавлении названия, которое уже есть в списке (без учёта регистра, «ё» и знаков препинания), сайт спросит подтверждение.
- **Ответы и реакции.** Под комментариями и ответами можно продолжать обсуждение и ставить 👍, 🔥, ❤️, 😁, 👀, 🤣, 😢 или 👎 (по одной реакции от каждого; на свой комментарий реагировать нельзя). Свои ответы можно изменять и удалять; ответы на удалённый комментарий сохраняются.
- **Статистика для двоих.** Средние оценки, совпадение вкусов, распределение оценок и просмотры за последние 12 календарных месяцев. На диаграмме «S против L» нажмите на точку или выберите её клавишей Tab и нажмите Enter, чтобы увидеть названия. Общий топ включает только то, что оценили оба.
- **Жанры и фавориты.** Сравнение по жанрам учитывает только просмотренное: средние оценки каждого, число общих оценок и степень близости (100% минус средняя разница оценок, делённая на 9). При менее трёх общих оценках результат отмечается как предварительный. Фаворит текущего календарного месяца выбирается среди просмотренного с датой не позже сегодня и оценками обоих; при равенстве показаны все лидеры. В «Самых спорных просмотрах» названия открывают карточку с обсуждением.

## Как дать доступ второму человеку

1. В репозитории: Settings → Collaborators → Add people — добавьте его аккаунт (права записи).
2. Он принимает приглашение, создаёт свой classic-токен со scope `public_repo` (см. выше) и вставляет его через ⚙ на сайте.

Каждое изменение коммитится от имени того, чей токен использовался; поле `updatedBy` у изменённого элемента хранит логин автора.

## Схема данных `data/movies.json`

Файл имеет вид `{ "version": 1, "types": [ { "key": string, "label": string, "color": string }, ... ], "items": [ Item, ... ] }`.

Список категорий хранится в массиве `types` (по умолчанию: фильм, сериал, аниме, шоу/офлайн). Поля элемента:

| Поле        | Тип                          | Описание                                                        |
| ----------- | ---------------------------- | --------------------------------------------------------------- |
| `id`        | string                       | Уникальный идентификатор (для новых — `crypto.randomUUID()`)    |
| `title`     | string                       | Название                                                         |
| `type`      | string                       | Ключ категории из `types` (например, `"movie"`, `"series"`, `"anime"`, `"show"`) |
| `genres`    | `string[]` (необязательно)    | Жанры, без пустых значений и повторов без учёта регистра |
| `tmdb`      | object (необязательно)       | Метаданные: `{ id, mediaType: "movie" \| "tv", originalTitle, year, overview, posterPath, runtime, imdbId? }`. Год, постер и длительность могут быть `null`; токен сюда не входит. Дубли определяются по паре `mediaType` + `id`. |
| `status`    | `"planned" \| "watching" \| "watched" \| "dropped"` | Статус: хочу посмотреть, смотрим, просмотрено, брошено |
| `ratings`   | `{ "S": 1..10 \| null, "L": 1..10 \| null }` | Оценки двух зрителей, S и L, каждая отдельно          |
| `comments`  | `{ "S": string, "L": string }` | Комментарии двух зрителей, каждый пишет только свой (пустая строка — нет комментария) |
| `replies`   | `Reply[]` (необязательно) | Ответы: `{ id, to, by, text, at, editedAt? }`; `to` — `"S"` / `"L"` для корневого комментария или `id` другого ответа, `by` — `"S"` / `"L"`, даты — строки ISO |
| `reactions` | `{ [target]: { S?: kind, L?: kind } }` (необязательно) | Реакции на корневой комментарий (`"S"` / `"L"`) или ответ (`id`); `kind` — `"like"`, `"fire"`, `"heart"`, `"grin"`, `"eyes"`, `"laugh"`, `"sad"` или `"dislike"` |
| `note`      | string                       | Заметка (может быть пустой)                                      |
| `addedAt`   | `"YYYY-MM-DD"`               | Дата добавления                                                  |
| `watchedAt` | `"YYYY-MM-DD"` или `null`    | Дата, когда отметили просмотренным                               |
| `droppedAt` | `"YYYY-MM-DD"` или `null` (необязательно) | Дата перехода в «Брошено»; отдельно от даты просмотра |
| `updatedBy` | string                       | GitHub-логин последнего, кто менял элемент (или пустая строка)   |

## Запуск локально

В корне репозитория:

```sh
python3 -m http.server
```

и открыть <http://localhost:8000>.

## Замечание про GitHub Pages

Публичная страница на GitHub Pages обновляется примерно через минуту после сохранения (время деплоя). Редактор же всегда читает свежие данные напрямую через GitHub API, поэтому у вошедшего пользователя изменения видны сразу.

## Недельные ветки данных

Код хранится в `master`, а оценки, комментарии и другие изменения списка — в ветках `data/YYYY-MM-DD_YYYY-MM-DD`. Даты обозначают понедельник и воскресенье недели по `Europe/Sofia`, с учётом летнего времени. Текущая ветка — последняя по имени среди существующих `data/*`. Пока таких веток нет, сайт продолжает читать и записывать данные в `master`.

При загрузке и перед каждой попыткой сохранения редактор заново определяет текущую ветку. В настройках ⚙ строка «Данные» показывает её имя. Гости читают опубликованную копию: workflow `Deploy Pages` берёт код из `master` и подставляет `data/movies.json` из текущей недельной ветки.

В ночь с воскресенья на понедельник, примерно в 00:05 по Софии, `Weekly rollover` собирает прошедшую неделю в один коммит данных на `master` и открывает новую недельную ветку. GitHub может задерживать расписание, поэтому предусмотрены повторные запуски; уже открытая неделя не обрабатывается повторно. Если данные не изменились, лишний коммит не создаётся. Старые ветки со всей историей сохраняются навсегда; история `master` не переписывается. Локальный `data/movies.json` на `master` может отставать от сайта на неделю.

После проверки и слияния изменений нужно один раз:

1. В `Settings → Pages → Build and deployment → Source` выбрать **GitHub Actions**.
2. В `Settings → Environments → github-pages → Deployment branches and tags` разрешить ветку `master` и шаблон веток `data/*`, если используется ограничение выбранными ветками.
3. Открыть `Actions → Weekly rollover → Run workflow`, выбрать `master`, включить `bootstrap`, оставить `dry_run` выключенным. Первая недельная ветка создастся из `master`, затем запустится деплой.

Для предварительной проверки в том же окне включите `dry_run`: скрипт напечатает план и ничего не отправит в репозиторий. Для локального теста предназначены `DRY_RUN=1`, `BOOTSTRAP=1`, `LATE_WAIT` (по умолчанию 180 секунд) и необязательный `NOW_OVERRIDE`; проверки выполняйте в отдельном тестовом репозитории. Рабочая зона времени — `TZ_NAME=Europe/Sofia`.

Если запуск красный, сначала проверьте журнал. При конфликте поздних изменений скрипт сохраняет обе недельные ветки и выводит конфликт: вручную перенесите нужные изменения из старой недели в `data/movies.json` текущей недели, разрешите конфликт и отправьте обычный коммит в текущую ветку. Старую ветку не удаляйте и не переписывайте. Повторный rollover для уже открытой недели будет пустым; восстановление поздних изменений нужно завершить вручную. Записи, пришедшие в старую ветку после окончания окна ожидания, также требуют ручного переноса. После исправления убедитесь, что `Deploy Pages` завершился успешно.

Переход выполняется без изменения настроек репозитория самим скриптом. Push через `GITHUB_TOKEN` не запускает другой workflow автоматически, поэтому rollover вызывает `Deploy Pages` явно после отправки изменений.
